# Ravenfield prototype

Прототип многопользовательского шутера на Go, raylib-go и Jolt Physics. Текущее состояние — завершённый технический Этап 0 из [`SPECIFICATION.md`](SPECIFICATION.md) и начало Этапа 1, а не игровой MVP. Устройство сети, ботов и техники описано в [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Что работает

- 3D-клиент на raylib-go с тестовой сценой и капсульным контроллером;
- сервер запущен всегда: одиночная игра идёт через встроенный сервер, к которому клиент подключается через память;
- сетевая игра по QUIC: выделенный сервер или клиент-хост; клиент предсказывает своего солдата и плавно показывает чужих;
- болванки для нагрузки: сотни серверных солдат без ИИ (`-dummies`), профиль тика по системам в журнале сервера;
- снимки в бюджете трафика: дельты от подтверждённого состояния каждого солдата, компактная запись ботов, приоритеты с конусом взгляда — 256 болванок укладываются в 32 КБ/с на клиента;
- физика Jolt 5.7.0 через собственный CGo/C++-адаптер;
- динамические тела, лучи и отладочная отрисовка;
- скелетные анимации Idle, Walking и Running;
- регдолл из 13 тел с переходом из текущей позы и обратным переносом на модель;
- единый тик симуляции 60 Гц на клиенте и сервере (`game.TickRate`);
- модель «игрок / солдат / бот» и квантованная команда ввода `game.InputCommand`;
- слои столкновений с масками для лучей, пакетные лучи на общем пуле потоков Jolt;
- сохранение и восстановление состояния персонажа: повтор команд с любого тика совпадает побитово;
- бинарный протокол: подключение, команды ввода и снимки мира со строгим разбором и fuzz-тестом;
- транспорт через QUIC и через память с имитатором сети (задержка, джиттер, потери, дублирование);
- консольный сервер без raylib;
- QUIC-прототип с надёжными потоками и ненадёжными датаграммами.

## Требования

Проверенная конфигурация: Linux x86-64, Go 1.27.1, GCC 16.2, CMake 4.4, Ninja.

Для сборки нужны:

- Go с поддержкой CGo;
- C++17-компилятор;
- CMake и Ninja;
- Git для загрузки Jolt через CMake FetchContent;
- системные библиотеки, необходимые raylib (OpenGL, X11/Wayland и аудио для клиента).

Windows подготовлена как целевая платформа архитектуры, но сборка и запуск на ней ещё не проверены.

## Сборка

Из корня репозитория:

```sh
make native
make all
```

Или полностью через цели Makefile:

```sh
make client
make server
make loadtest
go build -o bin/netprobe ./cmd/netprobe
```

После сборки нативной библиотеки все Go-пакеты можно проверить командой:

```sh
go build ./...
```

`make clean` удаляет собранные бинарные файлы и нативный build-каталог. При следующей сборке Jolt будет загружен заново.

## Запуск

Клиент:

```sh
./bin/client
```

Управление:

- `WASD` — движение;
- мышь — обзор;
- `Space` — прыжок;
- `Shift` — спринт;
- `K` — перейти из текущей анимации в косметический регдолл (смерть решает сервер с Этапа 2);
- `R` — вернуть солдата на точку появления через сервер, убрать регдолл и сбросить шары;
- `L` — уронить копии 16 ближайших солдат, чтобы проверить регдоллы: одновременно считается не больше 64, тела лежат 30 с;
- `F1` — отладочная отрисовка физики и серверное положение своего солдата рядом с предсказанным;
- `F2` — сетевой график;
- `F3` — вид от первого или третьего лица;
- `Esc` — захват или освобождение курсора.

Автоматическая проверка одного цикла:

```sh
./bin/client -demo -frames=600
```

Три цикла создания и удаления регдолла:

```sh
./bin/client -demo -cycles=3 -frames=2600
```

Солдат теперь добегает почти до колонны и падает на неё; регдолл успокаивается дольше, чем на открытом полу, поэтому кадров больше.

Автоматический маршрут с разгоном, рампой и прыжком:

```sh
./bin/client -movement -frames=400
```

Маршрут должен закончиться на верхней платформе: ступни на `Y=1.50`, `grounded=true`. Движение считает встроенный сервер; итоговая точка совпадает с той, что давал клиент до появления сервера.

Тот же маршрут через имитатор сети (задержка в каждую сторону, джиттер, потери):

```sh
./bin/client -movement -frames=400 -netsim=delay=40ms,jitter=10ms,loss=2%
```

Потерянные датаграммы перекрываются повтором последних команд, поэтому маршрут заканчивается в той же точке. Клиент предсказывает своего солдата, так что управление не запаздывает; строка `corrections` в журнале и на экране считает случаи, когда сервер с предсказанием не согласился.

Дополнительные параметры `-debug`, `-width`, `-height`, `-frames`, `-screenshot`, `-tuning`, `-name` и `-netsim` показаны в `cmd/client/main.go`.

Шары тестовой сцены — косметика клиента: сервер пока не передаёт динамические предметы, и солдат их не толкает.

Параметры движения по умолчанию заданы в `game.DefaultMovementTuning`. Файл `-tuning` в формате JSON переопределяет только указанные в нём значения, например:

```json
{"walk_speed": 5, "sprint_speed": 8, "jump_speed": 6, "eye_height": 1.55}
```

Неизвестное поле или недопустимое значение останавливает запуск с ошибкой.

Автоматические тесты:

```sh
go test ./...
```

Fuzz-тест разбора сетевых сообщений:

```sh
go test -run='^$' -fuzz=FuzzDecode -fuzztime=60s ./internal/network/protocol
```

## Сетевая игра

Сервер и клиенты общаются по QUIC поверх UDP: на сервере должен быть открыт **UDP-порт** (по умолчанию 7777), а для игры через интернет — проброшен на роутере тоже как UDP. У сервера и клиентов должна быть одна версия игры: при несовпадении версии протокола, карты или параметров движения сервер вежливо откажет.

### Выделенный сервер

```sh
make all
env -u DISPLAY ./bin/server -listen :7777
```

Сервер не открывает окно. При первом запуске он создаёт `server.crt` и `server.key` рядом с собой и печатает строку `certificate fingerprint …` — отпечаток сертификата. Ключ хранится между запусками, поэтому отпечаток не меняется; удалите оба файла, чтобы сделать новый.

Полезные параметры сервера:

- `-dummies=256` — болванки: солдаты-боты без ИИ, которые бродят по карте;
- `-max-players=16` — сколько людей пускать;
- `-client-bandwidth=32` — бюджет снимков на клиента, КБ/с;
- `-stats=5s` — как часто писать в журнал частоту тиков, время систем, трафик и память;
- `-seed=1` — зерно матча, чтобы расстановка болванок повторялась;
- `-duration=10m` — остановиться сам; без него сервер работает до `Ctrl+C`.

### Подключение клиента

```sh
./bin/client -connect 192.168.1.20 -name Alice
```

Вместо `192.168.1.20` — адрес машины с сервером: в локальной сети его показывает `ip addr` на сервере, через интернет — внешний адрес роутера с пробросом порта. Порт по умолчанию 7777; другой пишется через двоеточие: `-connect 192.168.1.20:9000`. `-name` можно опустить.

Отпечаток вводить не нужно. Как SSH, клиент при первом подключении к адресу запоминает отпечаток сертификата сервера в `~/.config/ravenfield/known_servers`, а при следующих проверяет его сам, до отправки любых данных. Если сертификат сменился — сервер переустановили или кто-то вклинился в соединение, — клиент откажется подключаться и напишет, что делать: если смена ожидаема, подключитесь один раз с новым отпечатком, и он заменит запомненный:

```sh
./bin/client -connect 192.168.1.20 -fingerprint <новый отпечаток>
```

Чтобы проверить сервер уже при первом подключении, сразу передайте `-fingerprint` с отпечатком из журнала сервера. `-config-dir` меняет каталог, где клиент хранит запомненные серверы; с пустым значением он ничего не запоминает.

### Игра с хостом без отдельного сервера

Клиент может сам стать сервером для друзей:

```sh
./bin/client -host :7777
```

Хост играет как обычно, а в журнале печатает `hosting on … certificate fingerprint …`. Друзья подключаются к его адресу командой из предыдущего раздела. Сертификат хоста хранится в `~/.config/ravenfield/host.crt` и `host.key`, поэтому отпечаток не меняется между запусками, и друзья, подключавшиеся раньше, доверяют хосту без лишних шагов.

### Обрыв связи

Если связь с сервером пропала — 5 с нет данных, — клиент не закрывается: он пишет `Connection lost` и раз в секунду переподключается сам, до минуты. Сервер всё это время держит за игроком его место и команду, а солдата убирает, чтобы им никто не управлял; вернувшись, игрок получает нового солдата в той же команде. Кто вышел из игры сам, освобождает место сразу. Время ожидания ввода и брони места на сервере задают `-input-timeout` и `-reconnect-window`.

### Проверка связи

- `F2` в клиенте (или флаг `-netgraph`) — сетевой график: RTT, потери снимков, трафик и число датаграмм, опережение команд и подстройка часов, опоздавшие команды, поправки предсказания и частота обновления солдата под прицелом.
- `-netsim=delay=40ms,jitter=10ms,loss=2%` у клиента — имитация плохой сети поверх настоящей.

Нагрузка из 256 болванок:

```sh
env -u DISPLAY ./bin/server -listen :7777 -dummies=256 -stats=2s
./bin/client -dummies=256
```

Журнал сервера показывает реальную частоту тиков, среднее и максимальное время тика, долю каждой системы, трафик снимков на игрока и память. Клиент рисует всех солдат одной моделью со скиннингом на GPU в цвете команды; оверлей показывает, сколько солдат нарисовано и сколько из них в полной детализации, а также трафик снимков за последнюю секунду.

Все 256 солдат в кадре — вид на карту сверху, без ограничения частоты кадров; итоговая строка журнала покажет среднюю частоту и самый долгий кадр:

```sh
./bin/client -dummies=256 -overview -max-fps=0 -frames=3000
./bin/client -dummies=256 -overview -max-fps=0 -frames=4000 -knockdowns=8
```

`-knockdowns=8` восемь раз через полсекунды роняет 16 ближайших солдат, как клавиша `L`.

Бюджет снимков: сервер шлёт каждому клиенту сначала его солдата, людей и тех, кто у перекрестия, затем остальных по приоритету. Посмотреть, как делится урезанный бюджет:

```sh
env -u DISPLAY ./bin/server -listen :7777 -dummies=256 -client-bandwidth=8 -seed=1 -stats=2s
```

### Нагрузочный тест

`bin/loadtest` запускает безголовых клиентов: они играют случайным вводом через весь путь настоящего клиента — QUIC, протокол, часы, предсказание, дельты снимков — но ничего не рисуют. Без `-connect` он поднимает свой сервер с болванками на `127.0.0.1`:

```sh
./bin/loadtest -clients=16 -dummies=256 -duration=10m -report=60s
./bin/loadtest -clients=16 -connect 192.168.1.20:7777 -fingerprint <отпечаток> -duration=10m
./bin/loadtest -clients=16 -duration=2m -netsim=delay=40ms,jitter=10ms,loss=2%
```

Каждый отчёт показывает на клиента тики и снимки в секунду, трафик, прыжки часов, поправки предсказания, опоздавшие команды, датаграммы без базы дельты, а также память процесса после сборки мусора. В конце печатается, как изменилась память с первой минуты. Если хоть один клиент отвалился или дельта не нашла базу, команда завершается с ошибкой.

QUIC-прототип:

```sh
./bin/netprobe -delay=40ms -drop-every=4
```

Параметр `-drop-every=4` отбрасывает каждый четвёртый UDP-пакет в обоих направлениях. Успешный запуск подтверждает восстановление надёжного потока и доставку датаграммы.

## Основные каталоги

- `cmd/client`, `cmd/server`, `cmd/loadtest`, `cmd/netprobe` — исполняемые программы;
- `internal/physics` — Go API физики и владение ресурсами;
- `native/jolt` — C ABI и C++-адаптер Jolt;
- `internal/animation` — скелетные анимации и регдолл;
- `internal/game` — общая симуляция: солдаты, команды, движение, параметры;
- `internal/simulation` — авторитетный сервер: сессии, очередь команд, снимки;
- `internal/client` — клиент: встроенный сервер, сессия, отрисовка;
- `internal/network/protocol` — бинарный протокол сообщений;
- `internal/network/transport` — QUIC, память и имитатор сети;
- `internal/network` — QUIC-прототип Этапа 0;
- `assets/prototype` — временная CC0-модель и её лицензия.
