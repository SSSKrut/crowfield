# Ravenfield prototype

Прототип многопользовательского шутера на Go, raylib-go и Jolt Physics. Текущее состояние — завершённый технический Этап 0 из [`SPECIFICATION.md`](SPECIFICATION.md) и начало Этапа 1, а не игровой MVP. Устройство сети, ботов и техники описано в [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Что работает

- 3D-клиент на raylib-go с тестовой сценой и капсульным контроллером;
- физика Jolt 5.7.0 через собственный CGo/C++-адаптер;
- динамические тела, лучи и отладочная отрисовка;
- скелетные анимации Idle, Walking и Running;
- регдолл из 13 тел с переходом из текущей позы и обратным переносом на модель;
- единый тик симуляции 60 Гц на клиенте и сервере (`game.TickRate`);
- модель «игрок / солдат / бот» и квантованная команда ввода `game.InputCommand`;
- слои столкновений с масками для лучей, пакетные лучи на общем пуле потоков Jolt;
- сохранение и восстановление состояния персонажа: повтор команд с любого тика совпадает побитово;
- бинарный протокол: подключение, команды ввода и снимки мира со строгим разбором и fuzz-тестом;
- транспорт через QUIC и через память с имитатором сети (задержка, джиттер, потери, дублирование);
- консольный сервер без raylib;
- QUIC-прототип с надёжными потоками и ненадёжными датаграммами.

## Требования

Проверенная конфигурация: Linux x86-64, Go 1.27.1, GCC 16.2, CMake 4.4, Ninja.

Для сборки нужны:

- Go с поддержкой CGo;
- C++17-компилятор;
- CMake и Ninja;
- Git для загрузки Jolt через CMake FetchContent;
- системные библиотеки, необходимые raylib (OpenGL, X11/Wayland и аудио для клиента).

Windows подготовлена как целевая платформа архитектуры, но сборка и запуск на ней ещё не проверены.

## Сборка

Из корня репозитория:

```sh
make native
make all
```

Или полностью через цели Makefile:

```sh
make client
make server
go build -o bin/netprobe ./cmd/netprobe
```

После сборки нативной библиотеки все Go-пакеты можно проверить командой:

```sh
go build ./...
```

`make clean` удаляет собранные бинарные файлы и нативный build-каталог. При следующей сборке Jolt будет загружен заново.

## Запуск

Клиент:

```sh
./bin/client
```

Управление:

- `WASD` — движение;
- мышь — обзор;
- `Space` — прыжок;
- `Shift` — спринт;
- `K` — перейти из текущей анимации в регдолл;
- `R` — сбросить персонажа, регдолл и динамические объекты;
- `F1` — отладочная отрисовка физики;
- `F3` — вид от первого или третьего лица;
- `Esc` — захват или освобождение курсора.

Автоматическая проверка одного цикла:

```sh
./bin/client -demo -frames=600
```

Три цикла создания и удаления регдолла:

```sh
./bin/client -demo -cycles=3 -frames=1600
```

Автоматический маршрут с разгоном, рампой и прыжком:

```sh
./bin/client -movement -frames=400
```

Маршрут должен закончиться на верхней платформе: ступни на `Y=1.50`, `grounded=true`.

Дополнительные параметры `-debug`, `-width`, `-height`, `-frames`, `-screenshot` и `-tuning` показаны в `cmd/client/main.go`.

Параметры движения по умолчанию заданы в `game.DefaultMovementTuning`. Файл `-tuning` в формате JSON переопределяет только указанные в нём значения, например:

```json
{"walk_speed": 5, "sprint_speed": 8, "jump_speed": 6, "eye_height": 1.55}
```

Неизвестное поле или недопустимое значение останавливает запуск с ошибкой.

Автоматические тесты:

```sh
go test ./...
```

Fuzz-тест разбора сетевых сообщений:

```sh
go test -run='^$' -fuzz=FuzzDecode -fuzztime=60s ./internal/network/protocol
```

Сервер без графического окружения:

```sh
env -u DISPLAY ./bin/server -duration=5s -stats=1s
```

Без параметра `-duration` сервер работает до `SIGINT` или `SIGTERM`.

QUIC-прототип:

```sh
./bin/netprobe -delay=40ms -drop-every=4
```

Параметр `-drop-every=4` отбрасывает каждый четвёртый UDP-пакет в обоих направлениях. Успешный запуск подтверждает восстановление надёжного потока и доставку датаграммы.

## Основные каталоги

- `cmd/client`, `cmd/server`, `cmd/netprobe` — исполняемые программы;
- `internal/physics` — Go API физики и владение ресурсами;
- `native/jolt` — C ABI и C++-адаптер Jolt;
- `internal/animation` — скелетные анимации и регдолл;
- `internal/game` — общая сцена и контроллер;
- `internal/simulation` — консольная серверная симуляция;
- `internal/network` — транспортный прототип;
- `assets/prototype` — временная CC0-модель и её лицензия.
